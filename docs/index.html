Model:Samples Firmware Tool Beta

Beta: still under testing. Keep the recovery route at hand.

The checks are verified against real files and the official firmware. The "Back to Samples OS" tab has only been tested against a simulated device, not yet on a real Model:Samples. Files from the "Install a Cycles OS" tab are byte-identical to Modded-Cycles' own builds, but have not been sent from this page to a real machine yet.

Put a modded Model:Cycles OS (Modded-Cycles or a derivative) on your Elektron Model:Samples, or bring it back to its own OS. Everything happens in this browser tab: nothing is uploaded.

What you need

  • A backup. Save your projects and samples with Elektron Transfer first.
  • Chrome, Edge or Opera on a computer, to send files over USB (Web MIDI). In other browsers you can still build and download the files, then send them with a SysEx tool.
  • A USB cable, and Elektron Transfer and Overbridge closed while this page sends.
  • The official OS 1.13 files from elektron.se (Support & Downloads): model-samples_OS1.13.syx, and for one of the ways back also model-cycles_OS1.13.syx. The page recognises them by their fingerprint.

    Activity

      What is checked, and what is not

      A file built for a real Model:Cycles must be Elektron's Model:Cycles OS 1.13 in everything but the OS: header, section table, bootstrap, updater and meta match Elektron's fingerprints, and its signature checks with the Model:Cycles key (derived from its own bootstrap, so the official Model:Cycles OS is not needed). The OS's update-check code must be intact, so the key fix applies safely. Only the OS is carried over, and only its 32 key bytes change, signed with the Model:Samples key. A file already packed for the Model:Samples is kept as it is, with the key fix added if it lacks it. The result must then pass every check of the Check a file tab.

      What the page cannot check is whether each mod works on a Model:Samples. Both machines run the same hardware and Modded-Cycles builds the same mods for both. If an OS ever fails to start, the STARTUP MENU brings the machine back.

      Credit: installing a Cycles OS on a Model:Samples, with the 32-byte key fix, is 18nelli18's work in Modded-Cycles (notes/41, notes/57). This tab builds the same files as its mods_for_samples.py, byte for byte.

      Bring a Model:Samples that runs a Model:Cycles OS back to its own OS over USB, the two ways 18nelli18's Modded-Cycles offers. The files are built here from your official OS files and must match Modded-Cycles' reference builds byte for byte.

      Before you start: back up your projects and samples with Elektron Transfer. Set every track that uses an added machine (7 and up) back to one of the six original machines. Close Transfer and Overbridge so this page can use the USB port.

          What is checked, and why

          An OS update for the Model:Samples is a SysEx stream carrying an ELE3 container with four sections: meta (5), bootstrap (2, holds the STARTUP MENU), MAIN OS (3) and updater (4), signed with HMAC-SHA256. A custom OS should replace section 3 only.

          • SysEx transport: start/end markers, packet count, sequence, every packet checksum, no stray bytes. Product 0x0F is the Samples' own transport. Product 0x11 is the transport for a Samples that already runs a Cycles OS installed for it.
          • Container: content checksum, header and section table identical to the official Model:Samples OS 1.13, the same load addresses and bootstrap version, a valid layout, and a container small enough for flash (≤ 0x1c0000 bytes from 0x20000).
          • Protected sections: bootstrap, updater and meta are compared with fingerprints of Elektron's own. A changed bootstrap is the one thing that can brick the device, so it is never accepted.
          • Signature: valid with the Model:Samples key, which is derived from the file's own verified bootstrap. Otherwise the device refuses the file ("Upgrade Failed") and writes nothing.
          • MAIN OS: unpacks without error. When the bootstrap unpacks it in place (input at 0x40200000, output from 0x40000400), the output never overtakes unread input. For a Model:Cycles OS, the update-check code must be intact and the 32-byte key fix must be present, so the official Samples OS can come back over USB.
          passwarning: flashable, read it fail: refused or won't boot, recoverablecritical: brick risk

          The page stores no Elektron firmware bytes and no key, only SHA-256 fingerprints of the official OS 1.13 parts. Format and rules come from Modded-Cycles (mtlib, mods_for_samples.py, notes 02/41/57) and the in-place boot layout from Supermodel (notes/41 §9).

          Recovery: the STARTUP MENU

          If an OS does not start, or an update over USB keeps failing, the STARTUP MENU brings the machine back. It is part of Elektron's bootstrap, which nothing on this page changes, so it works whatever OS is installed.

          1. Connect a MIDI interface to the Model:Samples' MIDI IN (USB does not work in this menu).
          2. Hold FUNC while switching the machine on.
          3. Press TRIG 4 (OS UPGRADE).
          4. Send the official model-samples_OS1.13.syx with a SysEx tool. An smp-os file from the Install tab works too; a cyc-os file does not. It is slow: a few minutes at MIDI speed.

          Sending a file with a SysEx tool

          A SysEx tool sends a .syx file to a MIDI port as it is. Use one when this page cannot send (no Web MIDI), or for the STARTUP MENU. For example:

          • Elektron C6 (Windows, macOS): Elektron's own free SysEx utility, from elektron.se.
          • SysEx Librarian (macOS) or MIDI-OX (Windows): free, general-purpose.
          1. Close Elektron Transfer, Overbridge and other music software, so the port is free.
          2. Pick the port: the Model:Samples' own USB port, or, for the STARTUP MENU, the MIDI interface wired to its MIDI IN.
          3. Open the .syx and send it. Confirm on the machine if it asks, and do not switch it off while it writes and restarts.

          Which file goes where: an smp-os file or the official model-samples_OS1.13.syx goes to a Model:Samples on its own OS over USB, or to the STARTUP MENU over MIDI IN. A cyc-os file goes only over USB, while a Cycles OS with the key fix runs. A file with the old packet numbering (Check a file warns about it) does not get through a SysEx tool: use its “Download the fixed .syx” first. Over MIDI IN, a whole OS takes a few minutes.

          Which OS does my Model:Samples run?

          • Connect it on the Install or Back tab. It answers as a Model:Samples on its own OS, and as a Model:Cycles on any Cycles OS. Elektron Transfer shows the same name.
          • With or without the key fix? The machine cannot say. If you installed it with Modded-Cycles, a derivative or this page, it has the key fix. If you used elektron-firmware-tool or a plain Model:Cycles file, it does not. Still have the file you installed? Drop it on Check a file: its last check says whether the key fix is there.
          • Still unsure? Try the first way on the Back tab: an OS without the key fix refuses it (“Upgrade Failed”) and nothing changes.

          Words used on this page

          Cycles OS
          The Model:Cycles operating system, with or without mods. The Model:Samples has the same hardware and can run it.
          Key fix
          A 32-byte change to a Cycles OS (from Modded-Cycles) that lets it accept updates signed for the Model:Samples. Without it, the only way back over USB is the two-file one, or the STARTUP MENU.
          smp-os / cyc-os
          The same packed OS in two wrappings. smp-os is for a machine on its own Model:Samples OS, or the STARTUP MENU. cyc-os is for a machine already on a Cycles OS with the key fix, over USB.
          SysEx tool
          A program that sends a .syx file to a MIDI port as it is, for example Elektron C6. See sending a file with a SysEx tool.
          STARTUP MENU
          Elektron's recovery menu (FUNC + power on). It takes only Model:Samples files, over MIDI IN. See recovery.
          Web MIDI
          How a browser talks to MIDI devices. Chrome, Edge and Opera have it; the page must be served over https (or python3 -m http.server), not opened as a file.
          Not affiliated with Elektron. A passing check lowers the risk; it does not guarantee that the OS itself works. Back up your projects and samples with Elektron Transfer before flashing.
